## 문서 유지 규칙 (지침서·CLAUDE.md·README를 고칠 때마다 지킨다)
1. **본문에는 지금 유효한 규칙만** 현재형으로 쓴다. 옛 값, 바뀐 경위, 사용자 인용, 날짜는 본문에 두지 않는다.
2. 규칙이 바뀌면 **그 자리의 문장을 고쳐 쓴다.** 뒤에 "개정:"·"N차 보강"을 덧붙이지 않는다. 서로 어긋나는 옛 문장이 남지 않게 같은 절을 끝까지 읽고 고친다.
3. 바뀐 사실은 그 장 파일 맨 아래 **개정 이력**에 한 줄(날짜 · 무엇 · 왜)로만 남기고, 장 맨 위 **최종 수정** 날짜를 바꾼다. 큰 결정은 `docs/guideline/00-header-decisions.md` 연표에도 한 줄 넣는다.
4. 절 번호는 바꾸지 않는다(다른 장·코드 주석이 번호로 가리킨다). 새 규칙은 맞는 절 안에 넣고, 맞는 절이 없을 때만 새 번호를 끝에 붙인다.
5. 같은 수치·경로·도구 이름이 다른 장, `CLAUDE.md`, `tools/README.md`, `tools/art_spec.md`에도 있으면 `grep`으로 찾아 **같은 커밋에서 함께** 고친다.
6. 나열은 표나 짧은 목록으로 쓴다(한 문단에 규칙 여러 개를 이어 쓰지 않는다).
7. 모든 장이 이 형식이다. 새 장을 만들 때는 기존 장의 틀(제목 → 최종 수정 줄 → 본문 → 개정 이력)을 따른다.

### 12-1. 작업 순서

**세부**
1. **언어 확인**: 한국어면 영어로 번역(0장 4번).
2. **길이 확인**: 단어 수 ÷ 145(남성 `am_michael` 실측, 9-2).
   - 목표 약 2,000~2,100단어, 허용 1,900~2,200(영상 15분 이내, 우주 모드도 같음).
   - 미만이면 10장 구조로 보강한다(보강 사실은 **A등급만**, 출처 기록). 초과면 반복·곁가지를 덜어낸다.
   - 채팅에 "원래 ○단어 → ○단어, 추가/삭제 내용"을 짧게 쓴다.
3. **사실 확인 (등급제)**: 모든 사실 주장을 표로(항목 | 원문 | 등급 | 처리·근거).

   | 등급 | 뜻 | 처리 |
   |---|---|---|
   | **A** | 출처로 확인된 사실 | 단정. 가장 자극적인 A를 앞에(훅, 반전) |
   | **B** | 출처가 가설·추정으로 밝힌 내용 | "scientists suspect…", "one hypothesis is…"로 |
   | **C** | 근거를 못 찾은 주장 | 지우거나 "No one knows for sure" 같은 미스터리 훅으로(모른다는 것 자체가 사실이어야 함) |
   | **D** | 근거와 모순 | 반드시 고치고 표에 표시 |

   - **지어내지 않는다**: 존재하지 않는 사례·연구·숫자·인용·인물 금지. 자극은 사실의 배열로.
   - A~D 처리를 반영한 내레이션으로 만들고 표에 표시한다. 애매하면 한 단계 보수적으로(A가 아니라 B).

   3-1. **훅 점수(참고용)**: 대본 첫 15초(첫 문단) 훅 후보 3~5개를 한 줄씩 `hooks.txt`에 적어 `python3 tools/writing/hookscore.py hooks.txt`로 점수를 본다(`tools/writing/hooks.json` = 훅 공식 21개). 낮은 점수는 다시 볼 신호일 뿐이고 높은 점수가 성과를 보장하지 않는다. 10-2A(질문·가정·영화 훅)와 사실 확인이 우선이다.
4. **장면 설계**: 컷, 등장인물·장소 시트, 칠판 구간, 효과음 큐, 팔레트(3-5).
5. HTML 애니메틱(13장).
6. 대본 txt(14장, HTML과 글자 하나까지 같게).
7. **그림 뒤 빌드**: `python3 tools/build/frog_place.py <slug>`(7-2) → `build3.py`. 빌드 로그의 `motion sanity`·`direction sanity`(4-4)·`sfx auto`·`music style`(9-3·9-4)을 확인한다.
8. **MP4 렌더(15장)**: Actions 서버 렌더(15-5, 병렬 20-7)가 기본이다(대화로는 30MiB 한도라 MP4를 못 보낸다). 막히면 15-1~15-4의 이 환경 렌더.
9. 제목·설명 파일(17장). 타임스탬프는 렌더 MP4의 실제 컷 시각.
10. **Drive 저장(18장)**: 모든 산출물을 Git으로 보내 Actions가 Drive로 올린다. 썸네일·txt는 `render/<슬러그>/deliver/`.

**사용한 대본 보관 (`main` 브랜치)**
- 렌더를 올릴 때 영상을 만든 대본을 `used/`로 옮긴다(`git mv`). 파일 이름은 `<슬러그>__<원래 파일명>.txt`.

  | 대본 종류 | 위치 |
  |---|---|
  | `generators/daily.py` | `scripts/daily/used/` |
  | `generators/owl.py` | `scripts/owl/used/` |
  | `generators/igwahyung.py` | `scripts/igwahyung/used/` |

- 사용자가 채팅에 붙여 준 대본도 같은 이름의 원본이 `scripts/<daily|owl|igwahyung>/`에 있으면 그것을 옮기고, 없으면 메시지 본문을 그대로 저장한다.
- `used/`에는 붙여 준 원문 전체를 한 글자도 바꾸지 않고 둔다. 수정·팩트체크본은 `videos/<슬러그>/`에만 두고, `used/`에 슬러그당 파일은 원본 하나뿐이다.
- `scripts/<종류>/` 맨 위에는 아직 안 쓴 대본만 남는다.
- 영상 완료 확인: `python3 tools/check/used_check.py <슬러그>`가 OK.

## 0. 언어 규칙 (최우선, 아래 모든 규칙보다 우선)

**이 문서는 한국어지만, 영상에 들리거나 보이는 것은 전부 영어다.**
1. 내레이션(TTS), 자막, 칠판 텍스트(제목·부제·출처·서명 개그·결론·카드), 삽입 사진 라벨, 화면 텍스트(3-6): 영어만. 그림(SVG) 속에는 글자를 그리지 않는다(3-1).
2. 이미지/영상 생성 프롬프트는 영어.
3. 제작 명세 본문(연출·카메라·연속성 메모, HTML 조작 버튼·안내, 대본 txt 머리말)은 한국어 가능. 그 안의 영상용 문구는 영어.
4. 한국어 대본이면 먼저 자연스러운 영어 내레이션으로 번역해 한 줄로 알리고 그 영어 기준으로 작업한다.
5. 1920×1080 스테이지 안에 한글이 나오면 안 된다.
6. 숫자·단위·날짜는 영어 표기("2.461 billion years ago", "380,000 km").
7. 채널명은 항상 **"Miya's Note"**. 워터마크 로고는 원형 이미지만(글자 없음, 6장). 참고 채널 이름은 출력물에 쓰지 않는다.

## 1. 한 줄 요약

팔레트 배경 + 얇은 스케치 선·부드러운 빛의 2D 일러스트를 의미 단위마다 바꾸고(3.5초 이상, 초반 5분은 더 자주, 20-2), 카메라는 늘 천천히 움직이며(20-1) 다양한 전환(4-3)으로 잇는다. 남성 영어 내레이션 + 효과음 + 덕킹 배경음악, 하단 영어 자막(말하는 단어 노랑), 화면 텍스트(3-6), 숫자는 칠판. 본편 약 15분 이내 + 숏츠 5편(각 2:00~2:55).

## 12. 출력 형식 (대본을 받으면 이렇게 한다)

| # | 산출물 | 형태 |
|---|---|---|
| 1 | 채팅 답변 | 길이 조정 내역, 사실 확인 표, 산출물 안내(짧게, 21-4) |
| 2 | MP4 영상 | `<슬러그>.mp4`(15장). 렌더 실패·지연 시 알리고 나머지 먼저 |
| 3 | 썸네일 3장 (A, B, C — 2026-10-16) | `<슬러그>_thumbnail_A.png`, `_B.png`, `_C.png`(16장) |
| 4 | 자막 대본 txt | `<슬러그>_script.txt`(14장) |
| 5 | 제목·설명 txt | `<슬러그>_metadata.txt`(17장) |
| 6 | HTML 애니메틱(확인용 시안) | 단일 HTML(13장) |
| 7 | 숏츠 5편(MP4 + 대본 txt + 메타데이터 txt) | `<슬러그>-short1`~`-short5`(19장), 별도 렌더 |

장면별 상세 명세(12-3)는 채팅에 쓰지 않고 HTML 장면 패널에 넣는다.

### 12-1. 작업 순서
**영상 한 편의 전체 순서 (miya 2026-10-22, 다른 장의 순서 언급보다 우선): ① 대본 확인·수정(아래 1~3) → ② TTS(음성·단어 시간) → ③ 썸네일 3장 → ④ 그림 → ⑤ 렌더·Drive 업로드.** 썸네일은 시안 3장(접촉 시트)을 사용자에게 보여 주고 **통과/수정 답을 받은 뒤에만** ④로 넘어간다. 확인 전에는 그림 에이전트 실행·렌더·Drive 업로드(`deliver/`, `.deliver_only` 푸시 포함)를 하지 않는다. 수정 요청이면 고쳐서 다시 보이고 통과를 받는다.

1. **언어 확인**: 한국어면 영어로 번역(0장 4번).
2. **길이 확인**: 단어 수 ÷ 163. 목표 약 2,200단어, 허용 2,000~2,300(영상 15분 이내, 2026-10-24 새 채널 Miya's Note, 우주 모드도 같음). 미만이면 10장 구조로 보강(보강 사실은 **A등급만**, 출처 기록), 초과면 반복·곁가지를 덜어낸다. 채팅에 "원래 ○단어 → ○단어, 추가/삭제 내용"을 짧게. 음성을 만든 뒤 실제 길이가 15분을 넘으면 알리고 줄일지 묻는다.
3. **사실 확인 (등급제, 사용자 결정 2026-10-10)**: 모든 사실 주장을 표로(항목 | 원문 | 등급 | 처리·근거).
   | 등급 | 뜻 | 처리 |
   |---|---|---|
   | **A** | 출처로 확인된 사실 | 단정. 가장 자극적인 A를 앞에(훅, 반전) |
   | **B** | 출처가 가설·추정으로 밝힌 내용 | "scientists suspect…", "one hypothesis is…"로 |
   | **C** | 근거를 못 찾은 주장 | 지우거나 "No one knows for sure" 같은 미스터리 훅으로(모른다는 것 자체가 사실이어야 함) |
   | **D** | 근거와 모순 | 반드시 고치고 표에 표시 |
   - **지어내지 않는다**: 존재하지 않는 사례·연구·숫자·인용·인물 금지. 자극은 사실의 배열로.
   - A~D 처리를 반영한 내레이션으로 만들고 표에 표시. 애매하면 한 단계 보수적으로(A가 아니라 B).
3-1. **훅 점수 (참고용, 2026-10-22)**: 대본 첫 15초(첫 문단) 훅 후보 3~5개를 한 줄씩 `hooks.txt`에 적어 `python3 tools/hookscore.py hooks.txt`로 점수를 본다(`tools/hooks.json` = 훅 공식 21개, youtube-agent-skill MIT). 낮은 점수는 다시 볼 신호일 뿐 높은 점수는 성과 보장이 아니다(도구가 밝힘). 수정할 때도 10-2A(질문·가정·영화 훅)와 12-1 사실 확인이 우선이다.
4. **장면 설계**: 컷, 등장인물·장소 시트, 칠판 구간, 효과음 큐, 팔레트(3-5). 5. HTML 애니메틱(13장). 6. 대본 txt(14장, HTML과 글자 하나까지 같게). 7. 썸네일은 위 ③에서 TTS 직후에 만든다(16장, 사용자 확인 필수). 4~6의 그림·렌더는 썸네일 통과 뒤.
8. MP4 렌더(15장): Actions 서버 렌더(15-5, 병렬 20-7)가 기본(대화로는 30MiB 한도라 MP4를 못 보냄). 막히면 15-1~15-4의 이 환경 렌더.
9. 제목·설명 파일(17장), 타임스탬프는 렌더 MP4의 실제 컷 시각.
10. **Drive 저장(18장)**: 모든 산출물을 **Git으로 보내 Actions가 Drive로 올린다**(사용자 결정: PC가 꺼져 있을 수 있음). 썸네일·txt는 `render/<슬러그>/deliver/`.
    - **사용한 대본 보관 (miya 2026-10-22)**: 영상을 만든 대본은 렌더를 올리는 푸시에 함께 `scripts/used/<슬러그>__<원래 파일명>.txt`(`main_owl.py` 대본은 `scripts_owl/used/`)로 옮긴다(`git mv`, 사용자가 직접 준 대본은 같은 이름으로 복사해 저장). `scripts/`·`scripts_owl/` 맨 위에는 아직 안 쓴 대본만 남는다. 안 쓴 대본은 `scripts/`·`scripts_owl/` 맨 위에 그대로 있다.

## 21-4 (모든 작업에 적용)
- **모든 작업에 적용.** 단계마다 결과·계획·진행을 알리지 않는다. **최종 렌더가 Drive에 올라갔을 때(또는 질문받았을 때, 막혀서 결정이 필요할 때)만 1~3줄**로 알린다. 에이전트 보고도 8줄 이내.
- 그림·영상을 고칠 때는 전체를 고치기 전에 **예시 이미지 몇 장**으로 먼저 확인받는다.
- 확인하지 못한 것(예: 렌더 영상을 직접 보지 않음)은 그렇게 쓴다.

## 0. 언어 규칙 (최우선, 아래 모든 규칙보다 우선)

**이 문서는 한국어지만, 영상에 들리거나 보이는 것은 전부 영어다.**
1. 내레이션(TTS), 자막, 칠판 텍스트(제목·부제·출처·서명 개그·결론·카드), 삽입 사진 라벨, 화면 텍스트(3-6): 영어만. 그림(SVG) 속에는 글자를 그리지 않는다(3-1).
2. 이미지/영상 생성 프롬프트는 영어.
3. 제작 명세 본문(연출·카메라·연속성 메모, HTML 조작 버튼·안내, 대본 txt 머리말)은 한국어 가능. 그 안의 영상용 문구는 영어.
4. 한국어 대본이면 먼저 자연스러운 영어 내레이션으로 번역해 한 줄로 알리고 그 영어 기준으로 작업한다.
5. 1920×1080 스테이지 안에 한글이 나오면 안 된다.
6. 숫자·단위·날짜는 영어 표기("2.461 billion years ago", "380,000 km").
7. 채널명은 항상 **"Miya's Lab"**. 워터마크 로고는 원형 이미지만(글자 없음, 6장). 참고 채널 이름은 출력물에 쓰지 않는다.

## 1. 한 줄 요약

팔레트 배경 + 얇은 스케치 선·부드러운 빛의 2D 일러스트를 의미 단위마다 바꾸고(3.5초 이상, 초반 5분은 더 자주, 20-2), 카메라는 늘 천천히 움직이며(20-1) 다양한 전환(4-3)으로 잇는다. 남성 영어 내레이션 + 효과음 + 덕킹 배경음악, 하단 영어 자막(말하는 단어 노랑), 화면 텍스트(3-6), 숫자는 칠판. 본편 약 20분 + 숏츠 3편(각 2:00~2:55).

## 3. 일러스트 스타일 (새 레퍼런스 기준, 2026-10-09 사용자 결정, 2026-10-16 다시 기본)

**하지 않는 것**: 굵은 검정 외곽선·플랫 컬러(참고 채널 화풍), 동심원·방사선 배경(2026-10-10), 보라·마젠타·주황 기본값, 흰 배경 위 네온, 3D·실사·치비·과장된 만화 표정.

### 3-1. 화풍
- **배경은 장면마다 하나**: 종이(`paper_base`, 가는 연필 선) / 밤(`night_top`→`night_bottom`, 은은한 비네팅) / 노을(`dusk_stops` 3색). 색은 영상 팔레트에서(3-5). 영상 전체에서 섞되 한쪽이 절반을 넘지 않게.
- **선**: 얇은 손그림 선 2.5~4px(주인공만 6px까지), 곡선은 약간 흔들리게. 종이는 `paper_ink`, 밤은 `night_line`·`night_glow`.
- **음영**: 큰 형태는 부드러운 그라데이션·글로우, 질감은 해칭. 팔레트 강조색 4개를 주로.
- **인물**: 단순하고 품위 있는 실루엣, 점 눈, 절제된 표정, 다양한 피부색. **사람 비율·팔·손 (2026-10-17, `tools/art_spec.md` 6A·6B)**: 귀여운 비율(성인 5.5등신·아이 4.5등신, `tools/body.py`의 `kind='cute'` 기본), 팔은 관절이 보이지 않는 한 덩어리 곡선(`body.arm`), 팔꿈치는 아래팔이 실제로 움직일 때만(`elbow_moves=True`). 보이는 손은 모두 `tools/hands.py`(해부학 비율 6자세)로, 기본은 둥근 손이고 손가락은 필요한 장면(가리키기·쥐기·손 흔드는 클로즈업·손이 주제·손 자국)에서만. 사람 팔 움직임은 `mv-limb`(꼬리처럼 휘는 `mv-chain` 금지).
- 그림(SVG) 안에는 글자·숫자를 그리지 않는다(간판 포함). 글자는 3-6 화면 텍스트 층으로.

### 3-2. 가운데 물체 규칙 (줌 전환의 핵심)
- 모든 그림은 **정중앙 (960, 500)에 둥근 물체 하나**(지름 170~260px, 밝은 중심: 눈·렌즈·램프·해·달·세포·시계 등). 중요한 것은 그 위에 놓지 않는다.
- 배경은 장면 내용에 맞게 그림마다 따로(방, 풍경, 실험실, 현미경 시야, 노트, 타임라인 등). 이웃 컷과 같은 종류가 이어지지 않게, 12컷 중 같은 종류는 2컷 이하(`tools/art_spec.md` 5절).
- 가능하면 다음 장면의 가운데 물체와 닮게(모양 겹치기, 4-3).
- 가운데 물체는 모션 그룹 하나(`mv-core-<타입>`, 19종, 4-1). `mv-glint-core`로 두면 빌드가 자동 배정.
- 다른 시선 포인트는 왼쪽(x≈400)·오른쪽(x≈1500).

### 3-3. 소재와 연출 규칙
- 시대·장소를 정확하게(복식, 건물). 확인 안 된 디테일은 그리지 않는다.
- 도입·결말에 현대 일상 앵커(영어권 시청자 기준, 주제가 한국일 때만 한국 장면).
- 대본의 비유를 그대로 그림으로(자물쇠=종 장벽, 저울=득실).
- 과학 개념은 같은 화풍의 도해. 실존 인물 사실 묘사 금지. 실제 민족은 존엄하게. 죽음·식인·폭력은 분위기와 상징으로만.

### 3-4. 이미지 생성 프롬프트 템플릿 (영어, 생성 도구용)

### 3-5. 색 팔레트 (사용자 결정 2026-10-10: "색감이 보라색 아니면 주황색이다. 대본에 맞게 색감을 사용하자")

`tools/palettes.py`: `ocean`(바다·심해·강) · `forest`(숲·습지·식물·곤충) · `desert`(사막·사바나·불) · `ice`(극지·빙하·고산) · `lab`(과학·의학·데이터) · `history`(역사·옛 도시·배·고고학) · `space`(우주·물리·시간, 남색+금, 보라는 성운일 때만) · `storm`(전쟁·재난·날씨·산업) · `body`(인체·동물 생물학·음식) · `sunset`(노을·꿈·판타지에만, 기본값 아님). 우주 4종은 3-7.
- 팔레트마다 종이(`paper_base`, `paper_ink`), 밤(`night_top`, `night_bottom`, `night_line`, `night_glow`), 노을(`dusk_stops` 3색, `dusk_ink`), 강조색 4개, 전환 워시 색 3개.
- **고르는 법**: `config.py`에 `PAL_DEFAULT = '<팔레트>'`, 장면별로 `PAL = {'<art_theme>': '<팔레트>'}`. 대본 내용(장소·재료·분위기)으로 고른다. **팔레트는 뼈대(2026-10-16)**: 장면·단위마다 바꾸거나 색을 더해도 된다(개수 제한 없음, `pal` 밖의 색도 내용에 맞으면 사용).
- `PLAN=1`이 모든 단위에 `pal`을 넣는다. 사물 고유색(피부·동물·식물·물)은 등장인물 시트를 따르되 팔레트와 어울리게. 전환 워시도 장면 팔레트를 따른다.
- `PAL_DEFAULT`가 없으면 `sunset`이 나오고 `PLAN=1`이 경고한다. **새 영상은 반드시 고른다.** 색 값은 내가 정한 것이며 `palettes.py`에서 고친다.
- 썸네일도 영상 팔레트(16-6 4번).

### 3-6. 화면 텍스트 (사용자 결정 2026-10-11: "이미지에 자막만 나오는 영상인데 대본에 따라 적절한 텍스트를 넣자")

그림에는 글자를 그리지 않고 빌더(`tools/build3.py`)가 HTML 층으로 올린다. 그림 에이전트가 사이드카 JSON `labels`(0~3개)에 적는다(`tools/art_spec.md` 8절).

- **이름 라벨 `name`**: 화면의 생물·장소·시대·물건 이름을 그 단위가 말할 때. Fredoka 34px 둥근 알약(종이 배경: 크림 바탕+팔레트 먹색 글자·테두리 / 밤·노을: 반투명 검정+흰 글자), 대상까지 얇은 선과 점, 대상 옆 빈 곳.
- **숫자 배지 `num`**: 숫자·연도·크기·비율을 말할 때. Fredoka 44px 대문자, 왼쪽에 강조색 막대, 왼쪽 위 고정(가로 x 80·y 64, 세로 x 100·y 330).
- **말풍선 `say`**: 동물·이름 없는 사람·사물의 짧은 반응. Patrick Hand 42px, 흰 바탕 검은 테두리, 꼬리가 입을 가리킴.

1. **사실은 대본에서만**: 라벨은 그 단위 내레이션의 단어(대소문자 무시), 배지는 그 단위에서 말한 숫자("four", "two and a half"처럼 말로 한 것 포함)만.
2. **말풍선은 사실을 말하지 않는다**: 4단어·24자 이하, 숫자 없음, 감정·반응만("Still here!", "Hmm?"). 실존 인물·조롱 금지. 단위의 약 1/8(채널 결정).
3. **빈도(채널 결정)**: 단위의 약 절반에 1개 이상. 라벨은 처음 나올 때만(이웃 반복 금지), 배지는 숫자를 말하는 단위마다. 칠판에는 없음.
4. **시각**: 사이드카 `word`를 말하기 0.1초 전 0.25초 팝인, 컷 끝까지(`word` 없으면 컷 시작 약 0.4초 뒤). 배지는 왼쪽에서 0.3초 들어오며 첫 숫자가 0부터 0.9초 카운트업(형식 유지, `1000`~`2100` 연도는 세지 않음). 배지 유지는 20-2.
5. 라벨·말풍선은 그림과 함께 움직이고 글자 크기 유지, 배지는 화면 고정.
6. **안전 영역**: 가로 x 120~1800, y 80~860, 로고 모서리(x 1660 이상, y 190 이하) 금지 / 세로 x 100~940, y 300~1400. 얼굴·가운데 물체·말하는 대상을 가리지 않는다. 배지 단위는 그림 왼쪽 위(약 640×160)를 비운다.
7. **글자 수**: 이름 28자, 배지 26자, 말풍선 24자 이하.
8. **검사**: `labels_lib.check`가 빌드 때 1~7을 검사하고 어기면 멈춘다. 미리보기 `python3 tools/labelshot.py <슬러그> <미리보기 폴더> <uid…>`. 말풍선 내용·가림은 눈으로.

### 3-7. 우주 모드 (사용자 결정 2026-10-12: "우주과학 대본은 좀 더 화려한 느낌의 화풍과 우주의 아름다움을 보여주는 이펙트·색감·효과음이 필요")

우주과학 대본에만. `config.py`에 `STYLE = 'cosmic'` + `PAL_DEFAULT`(장면별 `PAL`). 그림 명세 `tools/art_spec.md` 11절(충돌 시 우선).
- **화풍(면과 빛 + 얇은 스케치 선)**: 배경 밤 70% 이상(종이·노을은 도입·결말 일상 장면만). 성운 층 = 방사형 그라데이션 3~4겹(캔버스의 40~90%, `accents`·`night_glow`, 불투명도 0.15~0.55, 가장자리 투명, 블러 필터 금지). 별 3단계 = 작은 별 120~250개, 반짝이는 중간 별 12~25개(`mv-glint-s1~s3`), 십자 광채 큰 별 2~4개(가운데 물체·핵심 대상은 피함). 천체 = 방사형 그라데이션 두 겹(본체+대기 글로우), 한쪽 림 라이트, 해칭 몇 줄, 얇은 윤곽선은 주인공 천체만. 3-2·3-6은 그대로.

## 4. 모션 규칙 (일러스트 장면)

### 4-1. 움직임 방식
- **카메라**: 모든 그림에 드리프트 카메라(20-1). 포커스 대상이 있는 컷은 사이드카 `focus [x, y, 배율]`(배율 1.5~2.2)과 `focus_word`(컷 대본에 있는 단어)를 두고, 그 단어를 말하기 **0.5초 전**에 1.4초 동안 가속·감속으로 확대한 뒤 컷 끝까지 정지. 한 컷에서 여러 번 움직이지 않는다. 가장자리 밖이 보이지 않게 확대 중심을 제한.
- **포커스 스포트라이트**: 확대 1.4초 동안 주변이 어두워짐(가운데 투명, 바깥 검정 50%, 원 반지름은 배율에 맞춰 화면 폭의 30%~62%). 라벨·말풍선은 그 위. 사이드카 `"spot": false`로 끔.
- 그림 전체 부유(±12px)·먼지 입자는 쓰지 않는다. 빠른 휩팬·흔들림·회전 금지. 움직임은 작고 자연스럽게.
- **인물·사물 동작 (필수)**: 인물 그림에 `mv-` 그룹 장면당 3~6개, 앞쪽 인물마다 최소 하나. 생물의 관절 모션은 20-6.

  - `mv-flame-*` `mv-spark-*` 세로 맥동 0.25~0.30초 · `mv-smoke-*` `mv-steam-*` `mv-cells-*` `mv-key-*` 위로 떠오름 · `mv-glint-*` `mv-lamp-*` `mv-lantern-*` `mv-beacon-*` 제자리 맥동(크기 1→1.06, 투명도 .85→1, 1.2~1.5초)

  `spin` 회전 초당 36°(렌즈·시계·행성) · `sway` 위쪽 축 ±14°, 1.4초(램프·종·열쇠) · `orbit` ±34px·±26px, 2.4초·3.1초(위성·곤충) · `glide` 좌우 ±60px, 2.6초(배·구름) · `heartbeat` 1.14→1→1.09→1 후 쉼, 0.9초(심장·세포) · `flicker` 투명도 .35~1, 1초(촛불·별) · `swell` 1→1.2, 2.2초(숨·풍선) · `tremble` ±5px·±1.5°, 0.07초(긴장·균열) · `approach` 컷 내내 1→1.3(발견·접근) · `reveal` 투명도 .15→1·크기 .6→1, 0.7초 후 정지(처음 등장) · `squeeze` 가로 .55·세로 1.2, 1.1초(세포·물방울) · `wobble` 30°·1.3배, 0.2초 뒤 탄성 복귀, 2.2초(충격 뒤) · `roll` −110→+110px·−180→+180°(구르는 것) · `pop` 0.15초 뒤 .2→1, 0.6초 back.out(새 등장) · `ping` 고리 1.3초마다 .85→1.8, 불투명도 .95→0(신호·경보) · `stamp` 1.8배·투명에서 쾅 0.28초+고리(결정·도장) · `flip` 가로 뒤집기 0.46초, 2.4초마다(동전·반전) · `draw` 윤곽 1.3초 후 채움(설계도·새 개념) · `drop` −18° 기운 채 떨어져 튐, 0.9초 bounce.out(떨어지는 것·결과)

- **구현 조건**: 유한 반복 GSAP 트윈(seek 가능), SVG 필터 금지. 인물 `id`는 서로 다르게, 정지 상태로도 자연스럽게. 인물 동작의 자연스러움은 확인하지 못함(사용자가 판단).

### 4-3. 장면 나누기와 전환 (사용자 결정 2026-10-09)

**장면 나누기**
- **한 장면 = 새 그림 한 장 = 대본 의미 단위 하나.** 길이 기준(최소 3.5초, 최대 단위 6.2초, 초반 5분·숏츠·느린 장면 값)은 20-2가 현행이다. 그림 장수 제한 없음(20분 본편 약 230~260장).
- 같은 그림을 확대·이동만 바꿔 여러 컷으로 쓰지 않는다. 컷이 바뀌면 그림이 바뀐다.

**전환 (같은 전환 연속 금지, 앞 두 번과도 겹치지 않게)**
- **줌**: 나가는 그림은 가운데 물체로 가속 확대(약 2.6배, 1.1초), 들어오는 그림은 확대 상태에서 감속(1.7초). 큰 구간 전환, "들여다본다".
- **모양 겹치기(`match`)**: 가운데 물체 자리(반지름 120px 원)에서 0.9초 원형으로 열림. 앞뒤 물체가 같은 위치·크기·색 계열이고 **같은 장면 안일 때만**.
- **슬라이드**: 오른쪽에서 0.7초, 나가는 그림은 폭 18%만 밀림(순서·나열·비교). **페이드**: 0.6초(같은 장소 시간 경과).
- **워시**(스케치→채색 자리): 배경색(종이 `#ece4d1`, 밤 `#14122b`, 노을 `#5a4562`)으로 0.45초 덮였다 0.45초 걷힘(새 개념).

- **쓰지 않음**: 색 막대(`blinds`, 2026-10-16 모든 영상에서 뺌, 코드는 남음), 점 격자/모자이크(2026-10-14 삭제).

### 9-3. 효과음 (채널 결정, 2026-10-09 개정)
내레이션을 가리지 않는 조용한 효과음을 그림·전환에 싱크. 음정(띠리링)이 있는 소리 금지. **상시 저음(드론) 앰비언트 금지**(2026-10-09 "웅" 소리 지적).
- **합성 소리 v2 (`tools/sfx_lib.py`, 2026-10-10)**: 25종 swish, hush(별칭 shimmer), tick, crackle, bubble, wind, bell, click, creak, drip, thud, chime, rustle, pop, pencil, page, cloth, woodblock, sand, rain, splash, step, breath, stone, flutter(+우주 6종, 3-7). 소리마다 변형 3개(큐마다 돌려 씀). bell·chime·hush는 음정 없는 소리로 대체됨. 전부 고역통과 150Hz, **피크 −24dBFS**, 스테레오 48kHz.
- **큐**: 전환(4-3), 포커스 → tick, 장면 사건 → 사이드카 `sfx [{name, word, vol}]`(그 컷 대본 단어). 화면에서 일이 일어나는 시각에 맞춘다. 0.9초 안에 겹치면 사건 > 전환 > 포커스로 하나만. 같은 소리 두 컷 연속 금지. 칠판은 분필 소리.
- 배경 소리는 그 장면에서만 짧고 낮게(장면이 바뀌면 끊음). 약 120Hz 아래를 계속 내는 소리 금지.
- 음량 **(제안, 실측 아님)**: 장면 소리는 내레이션보다 15~20dB 낮게, 큐는 피크 −24dBFS, 내레이션 중에는 4~6dB 더 낮게.
- 금지: 웃음소리, 비명, 과장된 코믹 효과음, 고통·사망을 자극하는 소리, 출처 불명·저작권 음원. 음원은 직접 합성(라이브러리 음원은 라이선스 확인한 파일을 사용자가 올릴 때만).
- 큐는 HTML 장면 데이터와 대본 txt에 함께 적는다. 소리의 자연스러움은 사용자가 듣고 판단(나는 들을 수 없음).

### 9-4. 배경음악 (채널 결정, 2026-10-10 — 9장 첫머리의 "배경음악 없음" 규칙을 대체)
저작권 없고 가사 없는 잔잔한 음악을 **직접 합성**(`tools/bgm_lib.py`, `build3.py`에 연결).
- 작곡: 4가지 코드 진행(Am-F-C-G 계열 등), 코드 하나 8초, 부드러운 패드(사인파+약한 배음, 좌우 미세 디튠) + 박마다 약 40% 확률의 작은 플럭. 같은 진행 연속 금지. 영상 길이만큼, 처음 3초 페이드인·끝 5초 페이드아웃. 샘플·외부 음원·보컬 없음(`seed=5`).
- 저음 없음: 250Hz 고역통과 + 4.5kHz 저역통과.
- **덕킹**: 내레이션 파일(`n##.wav`)에서 50ms 단위 음량 곡선. 말 구간(−48dBFS 이상, 0.6초 이하 틈은 이음)은 기준 음량, 틈에서는 +4dB(어택 0.25초, 릴리스 1.2초). 음악 파일에 미리 구움.
- **음량**: 말 구간 음악 RMS를 내레이션보다 **13dB 낮게**(`BGM_BELOW` 환경변수). 내레이션+음악 통합 음량은 내레이션만과 0.1 LU 미만 차이(측정).
- `NOBGM=1`이면 음악 없음.
- 모든 소리(내레이션·효과음·분필·음악)는 `build3.py`가 `mix.m4a` 하나로 미리 합친다(15-5).

**규칙**: 내레이션 우선. 한 영상 안에서 음색·템포를 바꾸지 않는다(진행만 바뀜). 칠판 구간에도 같은 음악. 숏츠도 같은 음악(길이만큼 따로 합성). 크기·느낌은 사용자가 듣고 판단, 조정은 `BGM_BELOW`, `bgm_lib.py`의 진행·플럭 확률.

## 13. HTML 애니메틱 규격

컷·자막·칠판·효과음 타이밍을 확인하는 재생 가능한 시안. 단일 HTML.

줄 시각 = 컷 길이 × (앞 단어 수 ÷ 전체 단어 수), 컷 길이 = 단어 수 ÷ 2.7초. MP4는 15-2·21-5.

### 13-9. 게시 전 확인

## 15. HTML → MP4 렌더링 (최종 결과물)

MP4는 별도 컴포지션(렌더 원본 `render/<슬러그>/`)으로 렌더한다. 13장 애니메틱은 그대로 렌더되지 않는다. SVG 그림 기준 MP4라는 것을 알리고, AI 생성 클립이 있으면 교체한다.

### 15-1. 도구와 검증 상태
- **HyperFrames**(`npx hyperframes@0.8.141`, Apache-2.0): 헤드리스 Chrome이 프레임마다 seek해 캡처, FFmpeg 인코딩. 출력 H.264 1920×1080 30fps, AAC 48kHz 스테레오.
- 확인: `data-volume` 0.5 = −6dB. **Kokoro는 모노 24kHz라 스테레오 MP4에서 약 3 LU 커진다 → 스테레오로 바꾼 뒤 정규화**(15-2). `hyperframes transcribe`는 이 환경에서 403(단어 시간은 21-5). `init`은 `~/.agents/skills/`에 스킬을 설치한다(사용자 PC에서 실행 시 알림).

### 15-2. 컴포지션 규칙
- 폴더 하나에 `index.html`과 GSAP·폰트·오디오·로고를 **모두 로컬 파일로**. 외부 CDN·폰트 링크 금지(`sub_timeline_script_failure`). GSAP는 `npm pack gsap@3.14.2`의 `gsap.min.js`.
- 루트에 `data-composition-id`, `data-start`, `data-duration`, `data-width="1920"`, `data-height="1080"`. 시간 요소는 `class="clip"`, `data-start`, `data-duration`, `data-track-index`.
- 애니메이션은 일시정지 상태 GSAP 타임라인 하나를 `window.__timelines["main"]`에 등록. CSS 키프레임·JS 타이머·`requestAnimationFrame` 금지(seek 불가).
- 소리는 파일 + `<audio>`(Web Audio는 렌더에 들어가는지 미확인). 현행은 `mix.m4a` 한 트랙(15-5).
- **SVG 필터 금지**(`feTurbulence`+확대에서 초당 3.84프레임까지 떨어짐). 종이 질감은 정지 알파 노이즈 PNG 한 장을 맨 위층에.
- 자막·칠판·로고는 5·6·7장 값.
- **자막 시각 검사**: 모든 자막이 `시작 < 끝`, 다음 시작 ≥ 이전 시작인지 타임라인을 만들 때 검사하고, 어긋난 줄은 앞뒤 사이로 제한. 컷 끝은 컷 경계를 넘지 않는다. 렌더 후 컷 경계·중후반 프레임에서 자막이 한 줄만 보이는지 확인. 시각 자체는 21-5의 단어 시간.
- **음량 (검증됨)**: 내레이션을 이어 붙인 파일을 **스테레오로 변환** → ffmpeg `loudnorm` 2패스(`I=-16.8:TP=-1.5:LRA=3.5`, 1패스 측정값 + `linear=true`) → 48kHz 저장 → 컷별로 자름. 최종 MP4도 `ebur128`로 측정(9-2).

### 15-3. 렌더 명령 (샌드박스)
```
export HYPERFRAMES_BROWSER_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome
npx --yes hyperframes@0.8.141 render
```
- 설치된 Chromium 지정(자동 다운로드는 프록시 403). 결과는 `renders/`의 MP4(`ffprobe`, 프레임 몇 장, `volumedetect`로 확인).
- **긴 렌더는 분리 실행**(`&`만 쓰면 `render_cancelled_parent_exited`): 끝나면 `render.done`에 `EXIT <코드> SECONDS <초>`를 쓰는 `run_render.sh`를 `setsid nohup ./run_render.sh < /dev/null > /dev/null 2>&1 & disown`으로(이 호출만 따로). `pkill -f hyperframes` 금지. `tools/tts.sh`도 같은 방식.
- 진행은 `render.log`의 `"done":N`(6분 동안 안 늘면 멈춤, 100% 뒤 `Assembling final video`에서 0으로 보이는 것은 정상). 중단되면 처음부터 다시.

### 15-4. 안전 원칙
- 새 도구는 빈 폴더 샘플로 먼저 검증. 애니메틱 원본은 건드리지 않는다.
- 버전 고정(`@0.8.141`), 올릴 때 샘플로 재확인.
- 작업 폴더 밖에 생기는 파일은 사용자에게 알린다.
- 도구 설명과 이 장이 다르면 직접 렌더한 결과를 따른다.

### 15-5. GitHub Actions 서버 렌더 + Drive 자동 업로드 (2026-10-09 확인)

MP4는 서버에서 렌더해 Drive로 바로 올린다(대화·GitHub를 거치지 않음).

- 저장소 `gequra-ship-it/Youtube-script-Daily`(비공개, 예전 이름 `ht`/`HT`; 옛 이름으로 연결돼 있으면 Actions API가 막힘 → `list_repos` 확인, `add_repo`(access: push), 로컬 `origin`도 변경).

- **렌더 원본** `render/<슬러그>/`: `index.html`, `gsap.min.js`, 폰트, 로고, 질감 PNG, `mix.m4a`(모든 소리를 미리 합침; `<audio>` 수백 트랙은 ffmpeg 5분 제한으로 실패. `SEPARATE_AUDIO=1`은 예전 방식). 100MB 넘는 파일은 일반 푸시 불가.
- **제어 파일**: `.dest`(Drive 폴더, 18장; 없으면 `<슬러그>/`, `-short`·`-short1`~`-short9`면 접미어 뗀 이름의 `short/`), `.outname`(Drive 파일 이름), `.skip_deliver`(`deliver/` 다시 안 올림), `.deliver_only`(렌더 없이 `deliver/`만; 재렌더하려면 지움).

**구조**

### 20-1. 카메라: 모든 그림이 천천히 움직이되, 절대 튀지 않는다

(처음 시험한 `maxu=4.5`/`4.8`은 컷 평균 3.2초로 너무 빨라 폐기.)
- **최소 화면 시간, 그림은 모두 사용 (2026-10-16, 롱폼에도 적용)**: 그림 수는 그대로 두고 문단 안에서 컷 시점을 옮겨(원래 단어 시점에 최대한 가깝게) 모든 그림이 최소 시간 머물게 한다. 문단이 짧으면 그림들이 시간을 똑같이 나눈다(버리지 않음). 로그 `cuts moved for min time`.
- 속도감은 컷보다 그림 안 움직임(`mv-`, 관절, 카메라, 속도선)으로. 새 영상은 그림 하나가 3.5초 이상 머물 수 있게 나눈다.

- **순서**: `tts.sh` → `audio_prep.py` → **`SLUG=<slug> python3 tools/align.py`**(문단 45개 약 4분) → `PLAN=1 build3.py` → 빌드. words.json이 없거나 대본 단어의 90% 미만만 맞은 문단이 있으면 `build3.py`가 문단 번호를 출력하고 멈춘다(`ALIGN_LOOSE=1`은 예전 추정으로 진행, 쓰지 않는다).
- **재시간 맞추기**: `plan.json`이 있으면 단위 나눔은 그대로 두고 시간만 새로 잰다. 새로 나누려면 `UNITS=new`(`remake.py`는 자동). 대본을 고쳤으면 `align.py`를 다시 돌리고 `UNITS=new`.
- 검증: 다른 모델(base.en)과 단어 시작 시간 차이 중앙값 0.06초, 상위 5% 0.2초.

## 17. 제목 · 설명 · 타임라인 · 출처 · 해시태그

> 최종 수정: 2026-11-14 · 본문은 지금 유효한 규칙만 담는다. 바뀐 경위는 맨 아래 개정 이력.

- 산출물은 `<슬러그>_metadata.txt` 한 파일이고, 내용은 **제목, 영상 설명, 타임라인, 출처, 해시태그**다. 모두 영어.
- 한국어 안내문·채널 소개(ABOUT) 문구는 넣지 않는다.
- 생성: `tools/build/gen_text.py`.

### 17-1. YouTube 공식 한도 (2026-10-09 확인)
| 항목 | 한도 |
|---|---|
| 제목 | 100자 |
| 설명 | 5,000자. 앞부분만 "더보기" 전에 보인다 |
| 챕터(타임라인) | 첫 타임스탬프 `00:00`, 오름차순 3개 이상, 하나 10초 이상. 직접 넣은 챕터가 자동 챕터보다 우선 |
| 해시태그 | 공백 없음, 제목 옆 최대 3개, 60개를 넘으면 모두 무시 |

### 17-2. 파일 형식 (고정)
```
=== TITLE ===
<제목 한 줄>

=== DESCRIPTION ===
<1~2문장, 약 260자 이하>

TIMELINE
00:00 <챕터 제목>
00:48 <챕터 제목>
...

SOURCES
- <대본·칠판이 밝힌 출처>

#MiyasNote #<해시태그> #<해시태그> ...
```
- 숏츠는 TIMELINE 없이 제목·설명·(출처)·해시태그.
- SOURCES는 대본이나 칠판 `Source:`가 밝힌 출처가 있을 때만 쓰고, 없으면 블록을 뺀다(지어내지 않는다).

### 17-3. 항목별 규칙
| 항목 | 규칙 |
|---|---|
| 제목 | 짧고 한눈에 관심을 끌 것. 질문형일 필요 없다. 직관형·은유형 둘 다 가능하고 하나로 고정하지 않는다. 약 50자 이하(모바일 피드는 약 40자까지 보임, 50자는 제안값), Title Case, 핵심 단어를 앞에 |
| 설명 | 1~2문장, 약 260자 이하. 영상의 핵심 질문이나 가장 의외인 사실(대본에서). `gen_text.py`는 `DESC`의 첫 문단만 쓰고 넘치면 경고한다 |
| 타임라인 | 롱폼 기준 5~10개, 영어 Title Case 5단어 이하, 렌더 MP4의 실제 컷 시작 시각(`mm:ss`). 모두 10초 이상, 첫 챕터 `00:00` |
| 해시태그 | 4~5개, 설명 맨 아래 한 줄. 첫째는 항상 `#MiyasNote`(0장 7번의 예외), 그다음 가장 중요한 주제어 둘, 나머지 주제어(CamelCase) |

- 제목 금지: 이모지, 전부 대문자, 영상에 없는 내용 약속, 썸네일 문구 반복, 대본에 없는 숫자.
- 제목 예(구조 확인용): `Why Deep Sea Creatures Grow Into Giants`(직관), `The Alien Living in Our Oceans`(은유).
- 제목 검사(참고용): `python3 tools/writing/title_lint.py --title "..." --thumb "..."`. 길이 50자, Title Case, 이모지, 과장어, 썸네일 중복, 썸네일 2~4단어를 본다. 도구 출처: youtube-agent-skill(MIT) `yt-package`.
- 타임라인 시각이 렌더 구성표(내레이션 배치 시각)에서 온 값이고 렌더된 MP4로 다시 재지 않았다면 채팅 보고에 "추정"이라고 적는다.
- 전체 금지: 한글, 이모지, 대문자 남발, 키워드 덤핑. 사실 확인은 12-1과 같다.

### 17-4. 사용자에게 넘기는 것
- 영상(MP4), 썸네일, 메타데이터 txt만 넘긴다.
- 대본 txt(`_script.txt`)와 렌더 리포트(`_render_report.txt`)는 넘기지 않는다. `gen_text.py`는 대본 참고본을 작업 폴더(`<WORK>/<슬러그>/build/`)에만 만든다. 렌더 리포트는 Actions 로그에만 남고 Drive에는 올라가지 않는다.

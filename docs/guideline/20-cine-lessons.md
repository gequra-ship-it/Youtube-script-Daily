## 20. 카메라·컷 길이·속도감·관절·병렬 렌더 (3D 실험에서 얻은 규칙, 3~4장·19장보다 우선)

> 최종 수정: 2026-11-14 · 본문은 지금 유효한 규칙만 담는다. 바뀐 경위는 맨 아래 개정 이력.

시네마틱 3D 실험에서 얻은 규칙을 SVG 도구(`tools/build/build3.py`, `tools/check/motion_check.py`)에 넣은 것이다. 3D 구현 자체는 `archive/miyas-lab-2026-10-24` 브랜치(2A).

### 20-1. 카메라: 모든 그림이 천천히 움직이되, 절대 튀지 않는다
1. 카메라 위치·확대는 한 그림 안에서 연속이고 시작·끝은 감속(ease)한다.
2. 바라보는 대상·거리를 한 프레임에 바꾸지 않는다(바꿔야 하면 로그 비율로 길게 보간).
3. 장면을 바꾸는 순간은 전환(4-3)이 맡는다.

- **드리프트 카메라(`build3.py`)**: 포커스 대상이 없는 그림에도 그림 길이 전체에 걸친 한 번의 `sine.inOut` 이동을 준다. 밀기(1→1.06배), 왼쪽 이동, 오른쪽 이동, 당기기(1.06→1배)를 차례로 쓴다. 4-1의 "포커스가 있을 때만 움직임"을 대신한다. 끄려면 `config.py`에 `DRIFT = False`.

### 20-2. 컷 길이
**원칙**: 카메라 트래킹·객체 모션이 화면을 이끌므로 컷을 자주 바꾸지 않는다. 새 그림이나 새 변화는 최소 8.5초(느린 장면 10초) 이상 간격으로, 내레이션 단어에 맞춰 나온다. 속도감은 컷보다 그림 안 움직임(`mv-`, 관절, 카메라, 속도선)으로 만든다.

**현재값 (`build3.py`, `PACE = 1.5` 적용 후)**

| 항목 | 롱폼 | 숏츠(`VERT=1`) |
|---|---|---|
| 최소 화면 시간(`minu`) | 8.5초 | 8.5초 |
| 느린 장면 최소(`minu_slow`) | 10초 | 10초 |
| 최대 단위 | 9.3초(초반 5분 8.25초) | 9.0초(느린 장면 11.25초) |

- `PACE = 1.5`는 모든 길이(`maxu`·`slow`·`minu`·`minu_slow`, 기본값과 `config.py`의 `HOOK` 모두)에 곱해진다.
- `HOOK`이 없을 때의 기본값(PACE 곱하기 전): 롱폼 `dict(until=300, maxu=5.5)`, 숏츠 `dict(until=999, maxu=6.0, slow=7.5)`, `minu` 5.667초, `minu_slow` 6.667초, 최대 단위 6.2초. `HOOK`에 `minu`가 없어도 기본 `minu`가 적용된다.
- 이미 만든 `plan.json`을 그대로 다시 빌드할 때만: `config.py`에 `PACE = 1`, 예전 단위 나누기는 `HOOK = None`.

**최소 화면 시간은 그림을 버리지 않고 맞춘다**
- 그림 수는 그대로 두고, 문단 안에서 컷 시점을 옮겨(원래 단어 시점에 최대한 가깝게) 모든 그림이 최소 시간 머물게 한다. 로그 `cuts moved for min time`.
- 문단이 짧으면 그림들이 시간을 똑같이 나눈다. 그래서 문단 하나에 그림이 많으면 최소 8.5초가 채워지지 않는다(숏츠 최단 컷 약 4.7~5초, 롱폼 실측 최단 3.85초). 빌드 로그 `min`으로 확인한다.
- 더 길게 하려면 그림 수를 줄여야 한다: `HOOK`의 `maxu`/`slow`를 키워 `PLAN=1`로 단위를 다시 나눈다(이미 그린 그림은 못 쓴다).
- 새 영상은 그림 하나가 8.5초 이상 머물 수 있게 나눈다.

**느린 장면**
- 대상: 숫자가 2개 이상이거나 설명 단어(because, which means, in other words, the reason, imagine, think of, for example, compared, percent 등)가 있는 문단.
- 최소 10초, 차분한 전환(fade·match·eye·iris·slide·zoom)만 쓴다. 로그 `slow scenes [...]`.
- `config.py`의 `SLOW = [장면 번호]`로 더하고 `NOT_SLOW = [...]`로 뺀다.
- `HOOK`의 `slow=8.5` 같은 값은 그림을 더 적게 나누므로 이미 그린 영상에는 넣지 않는다.

**그 밖**
- 숫자 배지: 별도 층. 최소 4.5초, 자기 그림이 끝난 뒤 2.5초까지 남되 다음 배지 전과 문단 끝에 사라진다.
- 그림 수를 바꿀 때: 예전 `plan.json` 보관 → `PLAN=1` → `tools/build/remap_art.py <예전 plan>`이 가장 많이 겹치는 예전 그림을 연결한다(예전 그림 `$MIYA_WORK/<slug>/art3_prev/`). 다시 만들기는 21장.
- 초반 연출 예: 별 궤적·별자리 선 그리기, 날아드는 줌, 행성 플라이바이, 유리처럼 깨지는 그림, 적색 편이 흡수선, 풍선 위 점이 멀어짐, 빨라지는 시대 카운터.

### 20-3. 속도감: 가속해서 화면 밖으로 빠져나가고 계속 새로 생긴다
- **속도선(`build3.py`)**: 우주 모드에서 단위 대본에 속도 단어가 있으면, 포커스 점(없으면 가운데 물체)에서 방사형 선 30개가 `power3.in`으로 가속해 화면 밖으로 나가고 다시 생긴다(seek 안전).
- 속도 단어: speed, fast, accelerate, racing, rush, launch, rocket, warp, hurtle, flee, recede, expand, explode, burst, blast, stream, zoom 계열.
- 사이드카 `"speed": true/false`로 켜고 끈다(우주 모드가 아니어도 `true`면 켜진다).
- 그림: 부스트는 엔진 뒤 `mv-flame` + 우주선이 작아지며 멀어지는 다음 그림. 중력 탈출은 움푹 꺼진 격자 → 격자가 튕기며 파문이 퍼지는 그림 순서.

### 20-4. 지루한 구간을 숫자로 찾는다
- `python3 tools/check/motion_check.py render/<slug> [--step 6]`: t와 t+0.5초 화면의 그림 영역 평균 변화(motion)와 6초 전과의 차이(change)를 재서, **motion < 0.6이고 change < 3인 샘플이 이어지는 구간**을 출력한다.
- 렌더 전에 돌려 그 구간에 그림이나 움직임을 더한다.
- 같은 장면을 여러 번 쓰면 매번 다른 각도·연출로 한다.

### 20-5. 렌더 검사와 작업 방식
- 렌더 리포트로 확인: 영상 길이 = 빌드 길이, 음량(약 −16.7~−16.8 LUFS), 피크(0 dBFS를 넘으면 알림). 확인 못 한 항목은 그렇게 쓴다.
- 렌더 방법은 20-7.
- 하위 에이전트: 동시에 2~3개(그림 에이전트는 3개까지, 21-3), 각자 다른 파일만, git 금지. 결과는 직접 그림·연속 프레임을 보고 받는다.

### 20-6. 생물은 관절 단위로 움직인다
몸을 통째로 흔들지 않고 관절점에서 꺾는다.

| 그룹 | 쓰는 곳 | 속성 |
|---|---|---|
| `mv-joint-<이름>` | 관절 하나(턱, 다리, 날개, 지느러미발, 관측 장치, 가리키는 손) | `data-pivot="x y"`, 선택 `data-amp`(기본 12°), `data-per`(반주기 초, 기본 1.1), `data-phase`(라디안) |
| `mv-chain-<이름>-1, -2, -3…` | 안쪽으로 겹쳐 넣은 마디 사슬(꼬리, 촉수, 뱀, 목, 더듬이, 해초) | 마디마다 `data-pivot`. 부모 회전이 자식을 데려가고, 끝으로 갈수록 진폭 ×1.35, 마디마다 0.55 rad 늦게 |

- 사람 팔에는 `mv-chain`을 쓰지 않는다(3-1).
- 구현 `tools/build/build3.py`(GSAP `svgOrigin`), 그리는 법 `tools/art_spec.md` 7절. 축 규칙은 4-7·4-8·4-12.

### 20-7. 병렬 렌더
- `render/.chunked`에 `"<slug> <구간 수>"`(여러 줄 가능)를 적어 `render-pipeline`에 푸시하면 `render-chunked.yml`이 구간별로 동시에 렌더한 뒤 합쳐 Drive에 올린다. 바로 시작되고 같은 이름을 덮어쓴다.
- 구간 수: `python3 tools/build/chunk_plan.py render/<slug>`(렌더 시간은 영상 길이의 약 3.9배, 구간당 약 30분 목표). `final_check`를 통과한 빌드(`.checked`)에만 사양을 내놓는다(15-8).
- 구간 나누기는 `tools/chunk_prep.py`가 한다. 공용 자산(글꼴·로고·gsap)은 `tools/assets`에서 구간 폴더로 링크된다.
- 합치는 단계 리포트로 확인: 구간별 프레임 수, `repeat_check kept=`(앞 프레임과 거의 같은 프레임을 뺀 수, 차이가 크면 멈춘 화면), 전체 길이(영상·음성), 음량·피크.
- 이전 실행의 구간 결과만 다시 합칠 때: `render-chunked` 수동 실행에 `reuse_run` = 그 실행 번호.
- 렌더 없이 `deliver/`만 올릴 때는 `"<slug> 0"`(15-5).
- 검증: SVG 페이지의 구간 화면이 원본과 픽셀 차이 0.0.

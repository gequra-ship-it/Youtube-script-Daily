## 20. 시네마틱 3D 실험에서 얻은 규칙 (2026-10-14~16, SVG 방식에 적용 — 3~4장·19장보다 우선)

2026-10-16 사용자: "지금까지 얻은 모션 움직임이나 카메라 무빙, 이펙트, 초반 5분, 숏츠 3개 2분 이상은 잘 섞어보자." SVG 도구(`tools/build3.py`, `tools/motion_check.py`)에 넣은 내용이다(3D 구현은 `archive/miyas-lab-2026-10-24` 브랜치).

### 20-1. 카메라: 모든 그림이 천천히 움직이되, 절대 튀지 않는다
- 규칙: ① 카메라 위치·확대는 한 그림 안에서 연속이고 시작·끝은 감속(ease). ② 바라보는 대상·거리를 한 프레임에 바꾸지 않는다(바꿔야 하면 로그 비율로 길게 보간). ③ 장면을 바꾸는 순간은 전환(4-3)이 맡는다.
- **드리프트 카메라(`build3.py`, 2026-10-16)**: 포커스 대상이 없는 그림에도 그림 길이 전체에 걸친 한 번의 `sine.inOut` 이동(밀기 1→1.06배 / 왼쪽 이동 / 오른쪽 이동 / 당기기 1.06→1배를 차례로). 4-1의 "포커스가 있을 때만 움직임"을 대신한다. 끄려면 `config.py`에 `DRIFT = False`.

### 20-2. 초반 5분과 숏츠는 화면을 더 자주 바꾼다
- **컷 길이 1.5배 (2026-10-22 사용자 결정)**: 카메라 트래킹·객체 모션이 화면을 이끌므로 컷을 덜 자주 바꾼다. `build3.py`의 `PACE = 1.5`가 아래 모든 길이(`maxu`·`slow`·`minu`·`minu_slow`, 기본값과 `config.py`의 `HOOK` 모두)에 곱해진다. 현재값: 최소 8.5초(느린 장면 10초, 2026-10-25 miya 상향: 모션이 들어가니 장면 전환이 너무 빠르게 느껴짐; `minu`/`minu_slow` 기본값 5.667/6.667 ×PACE, `config.py`의 `HOOK`에 `minu`가 없어도 이 기본값이 적용됨), 최대 단위 9.3초(초반 5분 8.25초, 숏츠 9.0초, 숏츠 느린 장면 11.25초). 아래 본문의 3.5/4.5/5.5/6.2/6.0/7.5초는 PACE 1.0 기준 수치다. 컷이 길어진 만큼 그림 하나 안의 모션·트래킹을 더 다양하고 길게(4-1). 이미 만든 `plan.json`을 그대로 다시 빌드할 때는 `config.py`에 `PACE = 1`.
- 기준: 새 그림이나 새 변화가 **최소 8.5초(느린 장면 10초) 이상 간격으로, 내레이션 단어에 맞춰**(PACE 1.0일 때 4~8초) 나온다(초반 5분과 숏츠는 특히).
- **기본값 (2026-10-17, `build3.py`)**: `config.py`에 `HOOK`이 없으면 롱폼 `dict(until=300, maxu=5.5)`, 숏츠(`VERT=1`) `dict(until=999, maxu=6.0, slow=7.5)`. 최소 화면 시간 5.667초×PACE=8.5초(`minu`, 느린 장면 `minu_slow` 6.667초×PACE=10초; 2026-10-25 이전 기본 3.5/4.5초), 최대 단위 6.2초(초반 5분 5.5초, 숏츠 6.0초, 숏츠 느린 장면 7.5초). `HOOK = None`이면 예전 단위 나누기(예전 `plan.json`을 그대로 다시 빌드할 때만). (처음 시험한 `maxu=4.5`/`4.8`은 컷 평균 3.2초로 너무 빨라 폐기.)
- **최소 화면 시간, 그림은 모두 사용 (2026-10-16, 롱폼에도 적용)**: 그림 수는 그대로 두고 문단 안에서 컷 시점을 옮겨(원래 단어 시점에 최대한 가깝게) 모든 그림이 최소 시간 머물게 한다. 문단이 짧으면 그림들이 시간을 똑같이 나눈다(버리지 않음). 그래서 문단 하나에 그림이 많은 영상(예: 숏츠, 단위 평균 5~5.5초)은 최소 8.5초가 실제로는 채워지지 않고 가장 짧은 컷이 약 4.7~5초로 남는다. 롱폼도 같다(우주의 끝 영상: 문단 하나에 그림이 여러 장인 곳은 최단 컷 3.85초, 2026-10-25 빌드 로그 `min`). 더 길게 하려면 그림 수를 줄여야 한다(`HOOK`의 `maxu`/`slow`를 키워 `PLAN=1`로 단위를 다시 나눔, 이미 그린 그림은 못 씀). 로그 `cuts moved for min time`.
- 속도감은 컷보다 그림 안 움직임(`mv-`, 관절, 카메라, 속도선)으로. 새 영상은 그림 하나가 8.5초 이상 머물 수 있게 나눈다(그림이 많은 문단은 균등 분할, 위 최소 화면 시간 참고).
- **느린 장면**: 숫자 2개 이상이거나 설명 단어(because, which means, in other words, the reason, imagine, think of, for example, compared, percent 등)가 있는 문단은 최소 10초(`minu_slow` 6.667×PACE 1.5), 차분한 전환(fade·match·eye·iris·slide·zoom)만. `config.py`의 `SLOW = [장면 번호]`로 더하고 `NOT_SLOW = [...]`로 뺀다. `HOOK`의 `slow=8.5` 같은 값은 그림을 더 적게 나누므로 이미 그린 영상에는 넣지 않는다. 로그 `slow scenes [...]`.
- **숫자 배지**: 별도 층, 최소 4.5초·자기 그림이 끝난 뒤 2.5초까지 남되, 다음 배지 전과 문단 끝에 사라진다.
- 그림 수를 바꿀 때: 예전 `plan.json` 보관 → `PLAN=1` → `tools/remap_art.py <예전 plan>`이 가장 많이 겹치는 예전 그림을 연결(예전 그림 `$MIYA_WORK/<slug>/art3_prev/`). 다시 만들기는 21장.
- 초반 연출 예: 별 궤적·별자리 선 그리기, 날아드는 줌, 행성 플라이바이, 유리처럼 깨지는 그림, 적색 편이 흡수선, 풍선 위 점이 멀어짐, 빨라지는 시대 카운터.

### 20-3. 속도감: 가속해서 화면 밖으로 빠져나가고 계속 새로 생긴다
- **속도선(`build3.py`)**: 우주 모드에서 단위 대본에 속도 단어(speed·fast·accelerate·racing·rush·launch·rocket·warp·hurtle·flee·recede·expand·explode·burst·blast·stream·zoom 계열)가 있으면, 포커스 점(없으면 가운데 물체)에서 방사형 선 30개가 `power3.in`으로 가속해 화면 밖으로 나가고 다시 생긴다(seek 안전). 사이드카 `"speed": true/false`(우주 모드가 아니어도 `true`면 켜짐).
- 그림: 부스트는 엔진 뒤 `mv-flame` + 우주선이 작아지며 멀어지는 다음 그림, 중력 탈출은 움푹 꺼진 격자 → 격자가 튕기며 파문이 퍼지는 그림 순서.

### 20-4. 지루한 구간을 숫자로 찾는다
- `python3 tools/motion_check.py render/<slug> [--step 6]`: t와 t+0.5초 화면의 그림 영역 평균 변화(motion)와 6초 전과의 차이(change)를 재서 **motion < 0.6이고 change < 3인 샘플이 이어지는 구간**을 출력. 렌더 전에 돌려 그 구간에 그림이나 움직임을 더한다.
- 같은 장면을 여러 번 쓰면 매번 다른 각도·연출.

### 20-5. 렌더 검사와 작업 방식
- 렌더 리포트로 확인: 영상 길이 = 빌드 길이, 음량(약 −16.7~−16.8 LUFS), 피크(0 dBFS를 넘으면 알림). 확인 못 한 항목은 그렇게 쓴다.
- 렌더 방법은 20-7.
- 하위 에이전트: 동시에 2~3개(그림 에이전트는 3개까지, 21-3), 각자 다른 파일만, git 금지. 결과는 직접 그림·연속 프레임을 보고 받는다.

### 20-6. 생물은 관절 단위로 움직인다 (3D 스키닝에서 가져옴)
- 몸을 통째로 흔들지 않고 관절점에서 꺾는다.
- `mv-joint-<이름>`: 관절 하나(턱, 다리, 날개, 지느러미발, 관측 장치, 가리키는 손). `data-pivot="x y"`, 선택 `data-amp`(기본 12°), `data-per`(반주기 초, 기본 1.1), `data-phase`(라디안).
- `mv-chain-<이름>-1, -2, -3…`: 안쪽으로 겹쳐 넣은 마디 사슬(꼬리, 촉수, 뱀, 목, 더듬이, 해초). 마디마다 `data-pivot`. 부모 회전이 자식을 데려가고 끝으로 갈수록 진폭 ×1.35, 마디마다 0.55 rad 늦게. 사람 팔에는 쓰지 않는다(3-1).
- 구현 `tools/build3.py`(GSAP `svgOrigin`), 그리는 법 `tools/art_spec.md` 7절.

### 20-7. 병렬 렌더 (SVG에도 사용, 3D에서 만든 방식)
- `render/.chunked`에 `"<slug> <구간 수>"`(여러 줄 가능)를 적어 `render-pipeline`에 푸시 → `render-chunked.yml`이 구간별 동시 렌더 후 합쳐 Drive에 올린다(같은 이름 덮어씀, 바로 시작). 구간 나누기 `tools/chunk_prep.py`. SVG 페이지 구간 화면이 원본과 픽셀 차이 0.0으로 확인됨.
- 구간 수: `python3 tools/chunk_plan.py render/<slug>`(렌더 시간 영상 길이의 약 3.9배, 구간당 약 30분 목표).
- 합치는 단계 리포트로 확인: 구간별 프레임 수, `repeat_check kept=`(앞 프레임과 거의 같은 프레임을 뺀 수, 차이가 크면 멈춘 화면), 전체 길이(영상·음성), 음량·피크.
- 이전 실행의 구간 결과만 다시 합칠 때: `render-chunked` 수동 실행에 `reuse_run` = 그 실행 번호.
- 예전 `render.yml`(한 작업, `render/.slug`)은 짧은 영상이나 여러 슬러그를 차례로 렌더할 때.
